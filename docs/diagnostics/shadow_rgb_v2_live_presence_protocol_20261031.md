# Shadow RGB v2: непрерывная диагностическая запись на Pi 5

Проверяем реакцию камеры и модели v2, пока два человека по очереди появляются
в поле зрения и выходят из него. Длительность 10 минут. Питание двигателей и
650-нм проектор выключены. Запись не открывает UART, ROS или сеть и не посылает
команды движения. Использует AR0234 1920×1200 MJPG @ 30 fps, auto_exposure=3,
gain=0. Рабочая стереокалибровка OV9281 не изменяется; глубина в этом опыте не
вычисляется.

На Pi использовать отдельное дерево репозитория:

```bash
cd /home/elwis/dev_ws/sie_v6_temperature_disabled_mvp
git fetch origin codex/shadow-rgb-detector-20261030
git worktree add --detach /home/elwis/dev_ws/sie_shadow_rgb_v2_live_20261031 \
  origin/codex/shadow-rgb-detector-20261030
```

Найти файл v2, сверить SHA-256
`5583d645afebd3d52706b76655662cb4ce16110b2a0b224af2cc806d0292d07b`.
Выбрать путь найденного файла в переменную `MODEL`. Не подменять активную v1:

```bash
find /home/elwis/dev_ws/model_artifacts -type f -name '*.onnx' -print
MODEL=/полный/путь/к/v2/best.onnx
sha256sum "$MODEL"
```

С выключенными моторами и проектором:

```bash
cd /home/elwis/dev_ws/sie_shadow_rgb_v2_live_20261031
/home/elwis/dev_ws/runtime_envs/sie_mvp/bin/python \
  vision_core/tools/probe_shadow_rgb_v2_live_presence.py \
  --model "$MODEL" --duration-s 600 --sample-interval-s 1 \
  --motor-power-state off --projector-state off \
  --scenario 'Два человека по очереди входят, движутся боком и выходят; время отмечаю вручную'
```

Пример физического сценария: 0–60 с пустой кадр; 60–150 с человек А;
150–180 с пусто; 180–270 с человек Б; 270–300 с пусто;
300–390 с А с боковым движением; 390–420 с пусто;
420–510 с Б с боковым движением; 510–600 с пусто.
Зафиксировать реальные времена входа и выхода по часам запуска, если они
отличались от плана. Оба человека не должны появляться одновременно, если
проверяем поочерёдную смену; отдельный совместный кадр даст статус
`MULTIPLE_TARGETS` и сам по себе полезен как диагностический отказ.

Скрипт сохраняет `session.json`, `frames.jsonl` (каждое обработанное наблюдение)
и не более одного исходного MJPEG-кадра в секунду в `images/`. В каждой записи:
driver timestamp начала экспозиции, возраст кадра до результата, свежесть
≤500 мс, список рамок, состояние, переход и номер визуального сегмента.
Непересечение соседних рамок записывается как `UNRESOLVED_SWITCH`, а не как
установленная личность. Количество потерь и повторных захватов без ручной
разметки реального присутствия нельзя трактовать как recall и FP rate.

Скрипт сам ограничивает место под кадры 1 GiB и оставляет 1 GiB свободного
диска. При прерывании или ошибке записывает частичный итог; итоговый путь
выводится в `Saved:`. Для анализа достаточно `session.json`, `frames.jsonl`
и заметок оператора о фактических входах и выходах; фотографии нужны, чтобы
проверять отдельные неоднозначные моменты.
