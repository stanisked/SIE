# First live-steered forward trial: startup fault and stop observation

Recorded 2026-10-28. Operator requested one 0.20 m supervised forward command after a successful moving-person camera-only preview. ESP32 was running `v4_2_live_steering_v1` and reported `READY`, zero PWM, no active command or fault before the trial.

Evidence: Pi summary `/home/elwis/.local/state/sie/evidence/v7_live_steered_forward_1793177770_6aa318a6/summary.json` and `http.jsonl`. The operator provided copies of both. The summary result was `STOP_NOT_CONFIRMED`, with one movement POST, two attempted steer POSTs and one attempted stop POST. The operator later reported that the cart physically stopped. The later `/status` retained boot session `24BC7B488C95F8A1`, state `FAULT`, `BREAKAWAY_NOT_FOUND`, no active command, both PWM values zero, and 148/138 final wheel counts (encoder estimate about 0.142 m average). This is encoder travel, not a measured floor displacement.

The HTTP journal shows `/move-forward-steered` accepted at host monotonic 7973.055 s. The first confirmed `/steer-update` was sequence 1 with zero bias during `STARTING`. At 7973.549 s, `/status` already showed `BRAKING`, fault latch `BREAKAWAY_NOT_FOUND` and zero PWM. The runner then attempted a second zero-bias steer update and `/stop`; both timed out with a 0.4 s HTTP deadline. Neither second POST has confirmed execution. There was no confirmed nonzero steering update in this trial.

The v1 firmware's bounded breakaway formula produced `min(202/2,191/2)=95` counts for the 0.20 m command. At approximately 396 ms after command start, right/left counts were 77/69. The fault's recorded brake-start counts were 100/90 at the 450 ms startup deadline, so the left wheel had not crossed 95. The firmware failed the startup check even though the cart had translated. After braking, counts settled at 148/138. This explains the `BREAKAWAY_NOT_FOUND` fault; it does not establish why the two later HTTP requests timed out.

Versioned v2 candidate changes only the steered forward endpoint's startup threshold to no more than 15 counts and checks the final encoder sample at its deadline. The Pi runner now avoids steer updates after `BRAKING` or a fault, polls for the terminal state, and checks `/status` for zero PWM even if the `/stop` HTTP response is lost. Nine dry-run tests and Python compilation passed; the v2 ESP32 sketch compiled with Espressif Arduino core 3.3.12. No v2 physical trial has occurred. Measurement admission and autonomous motion remain unchanged.
